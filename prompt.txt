一、项目定位

本项目不是做普通“新闻情绪分析因子”，也不是让大模型直接预测股票涨跌。

本项目要做的是一个“AI 量化研究智能体”：
它能够自动收集多源金融文本信息，包括新闻、公告、研报摘要、互动平台问答、社交媒体舆情、政策文件等；
然后进行事件抽取、实体链接、谓词化表示、规则归纳、另类因子生成、回测验证和研究报告生成。

核心目标是：
将非结构化舆情信息转化为可解释、可回测、可复用的另类因子。

二、要解决的问题

传统舆情因子通常是：

新闻/评论文本 → 情感分类 → 正面/负面分数 → 因子

这种方法过于粗糙，存在几个问题：
1. 只看情绪，不理解事件结构；
2. 无法区分“真的影响基本面”的信息和普通噪声；
3. 不知道事件影响路径；
4. 跨行业、跨主题泛化能力弱；
5. 因子缺乏解释性；
6. 很难自动发现新的因子假设。

本项目希望升级为：

多源金融文本
→ 事件抽取
→ 谓词化表示
→ 历史市场反应对齐
→ 规则归纳
→ 另类因子生成
→ 回测验证
→ 自动生成量化研究报告

三、项目核心创新

请重点围绕以下几个创新点设计项目：

1. 从“情绪分数”升级到“事件规则”
不是简单判断新闻正面/负面，而是抽取事件类型、影响主体、影响路径、证据强度、舆情扩散结构。

2. 从“人工构造因子”升级到“Agent 自动归纳因子”
Agent 可以从历史样本中自动发现：
什么样的事件组合、舆情结构、市场反应更可能产生未来收益、波动或风险。

3. 从“黑箱因子”升级到“可解释另类因子”
每个因子都需要给出：
触发规则、代表事件、历史样本、回测表现、适用场景、失效风险。

4. 从“单步 LLM 分析”升级到“多智能体量化研究工作流”
不同 Agent 分工协作，完成信息采集、事件理解、规则归纳、因子生成、回测验证和报告撰写。

四、项目系统架构

请设计一个多智能体系统，至少包括以下 Agent：

1. 信息采集 Agent
职责：
- 收集财经新闻、公告、政策、研报摘要、互动问答、社交媒体舆情等文本；
- 将文本关联到股票、行业、概念、产业链节点；
- 过滤无关信息和重复信息。

2. 事件抽取 Agent
职责：
- 从文本中抽取结构化事件；
- 识别事件主体、客体、事件类型、时间、行业、影响对象；
- 输出标准化事件格式。

示例事件类型：
- 政策利好
- 监管处罚
- 订单增长
- 供应链中断
- 高管变动
- 股权质押
- 财报异常
- 产品涨价
- 产能扩张
- 舆情负面扩散
- 投资者质疑
- 问询函压力

3. 谓词归纳 Agent
职责：
将事件和舆情信息转化为可计算谓词。

示例谓词：
- has_policy_support
- policy_directly_related_to_business
- has_regulatory_penalty
- penalty_related_to_core_business
- has_supply_chain_disruption
- supplier_dependency_high
- social_attention_spikes
- negative_opinion_persistent
- investor_questions_increase
- management_response_vague
- announcement_contains_uncertainty
- profit_growth_but_cashflow_declines
- institutional_attention_increases
- event_mentions_core_product
- event_has_short_term_price_impact

4. 规则归纳 Agent
职责：
从历史事件样本和后续市场表现中归纳规则。

规则形式可以参考：
谓词 A ∧ 谓词 B ∧ 谓词 C → 某类市场反应

示例规则：
- 政策利好 ∧ 公司主营业务高度相关 ∧ 舆情热度快速上升 → 短期主题动量增强
- 监管处罚 ∧ 涉及主营业务 ∧ 负面舆情持续扩散 → 合规风险因子上升
- 净利润增长 ∧ 经营现金流恶化 ∧ 投资者质疑增多 → 盈利质量风险上升
- 供应链中断 ∧ 公司供应商集中度高 ∧ 新闻扩散速度快 → 经营风险因子上升
- 管理层回应模糊 ∧ 投资者连续追问 ∧ 后续公告未澄清 → 信息披露不确定性上升

5. 因子生成 Agent
职责：
将规则转化为可计算的另类因子。

示例因子：
- policy_benefit_momentum_score
- regulatory_risk_score
- public_opinion_diffusion_score
- earnings_quality_risk_score
- supply_chain_risk_score
- investor_question_pressure_score
- management_vagueness_score
- event_attention_acceleration_score
- expectation_gap_score

每个因子需要定义：
- 输入数据
- 计算公式
- 时间窗口
- 标准化方法
- 股票覆盖范围
- 调仓频率
- 预期方向
- 可解释含义

6. 回测验证 Agent
职责：
对生成的因子进行量化验证。

至少包括：
- IC
- Rank IC
- ICIR
- 分组收益
- 多空组合收益
- 年化收益
- 最大回撤
- Sharpe Ratio
- 换手率
- 行业中性化
- 市值中性化
- 样本内 / 样本外测试
- 因子衰减分析
- 稳健性检验

7. 反思与审计 Agent
职责：
防止 Agent 编造因子有效性。
要求：
- 所有因子必须经过回测；
- 所有结论必须有数据支撑；
- 如果因子无效，要分析失败原因；
- 不允许只凭大模型直觉给出投资结论；
- 输出应为研究用途，不构成投资建议。

8. 报告生成 Agent
职责：
自动生成量化研究报告，包括：
- 因子假设
- 数据来源
- 事件谓词设计
- 规则归纳结果
- 因子公式
- 回测结果
- 可解释案例
- 风险与局限
- 后续优化方向

五、技术路线

请按照以下路线设计方案：

1. 数据层
- 多源文本数据：新闻、公告、政策、互动问答、研报摘要、社交媒体舆情；
- 市场数据：股票日频行情、成交量、市值、行业分类、指数收益；
- 公司基本面数据：财报指标、盈利、现金流、负债、估值；
- 事件标签数据：事件发生时间、关联股票、事件类型、后续收益窗口。

2. 表征层
- LLM 事件抽取；
- 实体识别与股票代码匹配；
- 事件谓词 schema 设计；
- 用户可以人工校正谓词；
- 将文本事件转化成结构化事件表。

3. 规则层
- 基于历史样本归纳规则；
- 候选规则可以是一阶谓词或二阶/三阶谓词组合；
- 规则评分需要结合未来收益、波动率、回撤、成交量异常等市场反应；
- 规则应有可解释文本描述。

4. 因子层
- 将规则触发情况转成因子值；
- 支持日频或周频因子；
- 支持行业中性化、市值中性化、标准化；
- 支持多因子合成。

5. 回测层
- 构建简单但可信的回测框架；
- 避免未来函数；
- 因子生成必须只使用当时可获得的信息；
- 按时间切分训练期、验证期、测试期；
- 展示因子有效性和稳定性。

6. Agent 层
- 多 Agent 分工协作；
- 每个 Agent 有明确输入输出；
- Agent 之间通过结构化中间结果传递；
- 最终形成“自动量化研究员”工作流。
