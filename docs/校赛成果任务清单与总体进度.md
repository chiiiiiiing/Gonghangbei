# AlphaLens 校赛成果任务清单与总体进度

版本：v0.1

日期：2026-07-12

内部提交目标：2026-08-15 前形成可提交校赛成果。

说明：官方通知中报名截止为 2026-08-17，作品提交截止为 2026-08-31 15:00。这里按团队更紧的内部目标 2026-08-15 倒排，目标是在 8 月 15 日前完成“可运行 Demo + 技术文档 + 演示 PPT + 数据与回测结果”的校赛成果包，后续留出时间补材料、修问题和排练。

## 1. 最终要交付什么

到 2026-08-15 前，至少要交付以下成果：

### 1.1 可运行 Demo

必须能现场演示一条完整链路：

```text
输入金融文本
-> 识别关联股票/行业
-> 抽取结构化事件
-> 生成事件谓词
-> 触发历史规则
-> 生成另类因子
-> 展示回测结果
-> 输出研究报告
```

最低要求：

- 能处理一批样本文本，而不是只处理单条文本。
- 能展示事件、谓词、规则、因子、回测之间的追溯关系。
- Demo 不依赖现场联网才能跑通。
- 有 1-2 个稳定案例可讲。

### 1.2 项目文档

必须包括：

- 项目立项书。
- 技术方案。
- 数据方案。
- MVP 说明。
- 算法方案。
- 回测方法说明。
- 风险与合规声明。
- 团队分工与进度安排。

### 1.3 演示 PPT

建议 12-16 页：

- 封面。
- 背景与痛点。
- 核心想法。
- 技术路线。
- 系统架构。
- 多 Agent 工作流。
- 事件谓词与规则归纳。
- 因子生成方法。
- 回测结果。
- Demo 展示。
- 创新点。
- 落地价值。
- 风险与局限。
- 团队与计划。

### 1.4 数据与样本

最低要求：

- 一个明确行业股票池。
- 一类主事件样本。
- 一批原始文本样本。
- 对应行情数据。
- 事件表、谓词表、规则表、因子表、回测结果表。

### 1.5 回测与图表

最低要求：

- IC / Rank IC。
- ICIR。
- 分组收益。
- 多空组合收益。
- 累计收益曲线。
- 最大回撤。
- Sharpe Ratio。
- 换手率。
- 样本内 / 样本外切分说明。
- 未来函数检查说明。

### 1.6 研究报告样例

至少自动生成 1 份因子研究报告样例，包含：

- 因子假设。
- 数据来源。
- 事件谓词设计。
- 规则归纳结果。
- 因子公式。
- 回测结果。
- 可解释案例。
- 风险与局限。
- 不构成投资建议声明。

## 2. 所有要做的事

下面先按工作包列全量任务，后续再按三人能力重新分配。

### 2.1 项目定位与比赛材料

- 明确参赛赛道：自拟赛题为主，对齐金融大模型与智能体、智能风控与量化建模。
- 明确项目一句话介绍。
- 明确项目边界：另类因子挖掘与量化研究辅助，不做股票涨跌预测，不构成投资建议。
- 整理比赛通知要点。
- 完成项目立项书。
- 完成精益画布。
- 完成原创性说明。
- 完成风险与合规声明。
- 准备答辩 FAQ。

### 2.2 MVP 范围确定

- 选择一个行业：建议新能源或半导体。
- 选择一类核心事件：建议政策利好 + 关注度扩散。
- 确定股票池规模：30-80 只。
- 确定时间范围：建议 2024-01-01 至 2026-06-30。
- 确定主因子：`policy_attention_momentum_score`。
- 确定调仓频率：周频。
- 确定持有期：5 或 10 个交易日。
- 确定训练期、验证期、测试期。
- 明确 Demo 只展示 MVP 范围，不承诺覆盖全市场。

### 2.3 数据准备

- 建立股票池清单：股票代码、简称、行业、概念、市值。
- 收集政策文本。
- 收集财经新闻摘要。
- 收集上市公司公告。
- 收集互动问答样本。
- 准备行情数据：交易日、收盘价、成交量、涨跌幅。
- 准备行业分类数据。
- 准备市值数据。
- 清洗文本：去重、去 HTML、统一时间格式。
- 建立样本数据目录。
- 建立数据字典。
- 保存数据来源和可复现说明。

### 2.4 数据表与中间结果设计

- 设计 `raw_documents` 原始文本表。
- 设计 `entity_links` 实体链接表。
- 设计 `events` 事件表。
- 设计 `predicates` 谓词表。
- 设计 `rules` 规则表。
- 设计 `factors` 因子表。
- 设计 `backtest_results` 回测结果表。
- 设计 `reports` 自动报告输出结构。
- 写字段说明文档。

### 2.5 LLM 事件抽取

- 设计事件类型列表。
- 设计事件抽取 JSON schema。
- 编写事件抽取 prompt。
- 编写输出格式校验逻辑。
- 实现文本批处理脚本。
- 抽样检查事件类型、主体、客体、时间、影响路径。
- 保存证据片段和置信度。
- 支持人工校正。

### 2.6 实体链接

- 建立公司简称、全称、股票代码映射。
- 建立行业和概念词典。
- 实现文本到股票代码匹配。
- 处理简称歧义。
- 输出实体链接置信度。
- 支持人工修正。

### 2.7 谓词 schema 与谓词判断

- 定义 8-12 个 MVP 谓词。
- 为每个谓词写自然语言解释。
- 定义每个谓词的数据来源。
- 定义谓词取值：布尔值或分数。
- 编写谓词判断 prompt。
- 实现谓词批处理脚本。
- 保存谓词判断理由。
- 抽样检查谓词质量。

### 2.8 规则归纳

- 将事件和谓词转成事件-谓词矩阵。
- 对齐未来收益、波动、回撤、成交量异常。
- 定义市场反应标签。
- 搜索单谓词规则。
- 搜索二阶谓词组合规则。
- 可选搜索三阶谓词组合规则。
- 设计规则评分函数。
- 设置 support 阈值。
- 输出 Top-K 规则。
- 为每条规则生成自然语言解释。
- 标记规则适用场景和失效风险。

### 2.9 因子生成

- 将规则触发转为股票-日期因子值。
- 加入事件时效衰减。
- 加入证据来源权重。
- 加入文本关注度加速度。
- 实现行业内标准化。
- 实现极值处理。
- 实现市值中性化，若数据允许。
- 输出因子表。
- 保存因子公式说明。

### 2.10 回测验证

- 读取行情数据。
- 计算未来收益。
- 处理停牌、缺失值、异常值。
- 严格避免未来函数。
- 按时间切分训练期、验证期、测试期。
- 计算 IC。
- 计算 Rank IC。
- 计算 ICIR。
- 计算分组收益。
- 计算多空组合收益。
- 计算年化收益。
- 计算最大回撤。
- 计算 Sharpe Ratio。
- 计算换手率。
- 做因子衰减分析。
- 做稳健性检验。
- 输出回测图表。

### 2.11 反思与审计

- 检查因子是否使用未来信息。
- 检查样本量是否过小。
- 检查规则是否过拟合。
- 检查回测结论是否夸大。
- 对无效规则给出失败原因。
- 对所有投资相关表述加研究用途声明。
- 输出审计说明。

### 2.12 Demo 页面

- 设计 Demo 页面信息架构。
- 展示输入文本列表。
- 展示实体链接结果。
- 展示事件抽取结果。
- 展示谓词矩阵。
- 展示规则触发。
- 展示因子排名。
- 展示回测曲线。
- 展示分组收益。
- 展示自动报告。
- 支持一键跑示例。
- 准备离线 Demo 数据。

### 2.13 自动报告生成

- 设计报告模板。
- 自动填充因子假设。
- 自动填充规则结果。
- 自动填充回测指标。
- 自动填充解释案例。
- 自动生成风险提示。
- 输出 Markdown 或 HTML。

### 2.14 工程与仓库

- 建立目录结构。
- 编写 README。
- 编写依赖说明。
- 编写运行命令。
- 准备样例数据。
- 准备一键运行脚本。
- 保证本地可复现。
- 定期提交到 GitHub。

### 2.15 答辩准备

- 完成 PPT。
- 准备 3 分钟版介绍。
- 准备 5 分钟版介绍。
- 准备 8 分钟版介绍。
- 准备 Demo 讲解脚本。
- 准备评委 FAQ。
- 准备项目创新性说明。
- 准备技术可行性说明。
- 准备商业/应用价值说明。
- 进行至少 2 次完整彩排。

## 7. 当前最应该马上做的三件事

1. 在 2026-07-14 前冻结 MVP：行业、事件、股票池、时间范围、主因子。
2. 在 2026-07-21 前拿到可用数据：至少 100 条文本、股票池和行情数据。
3. 在 2026-07-28 前跑通最小闭环：文本 -> 事件 -> 谓词 -> 规则 -> 因子 -> 回测。

等这三件事完成后，再重新分配三人职责会更合理：分工应围绕数据链路、算法回测链路、产品答辩链路来切，而不是一开始就按泛泛的“项目/数据/工程”切。
