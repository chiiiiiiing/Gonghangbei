# AlphaRIFT 三人团队分工与启动推进

版本：v0.1

日期：2026-07-12

目标：用三人团队在 5-7 周内完成一个可演示、可解释、可回测的 AlphaRIFT MVP，支持校赛报名、作品提交和现场答辩。

## 1. 三人角色分工

### 成员 A：项目负责人 / 量化研究 / 答辩统筹

核心职责：

- 明确比赛定位、MVP 范围和答辩故事线。
- 设计金融逻辑：事件如何影响收益、风险、波动或成交量。
- 设计因子定义、回测口径和评估指标。
- 负责最终 PPT、路演稿、FAQ、项目文档。
- 把控项目不偏成“LLM 预测股票涨跌”，始终强调“另类因子挖掘与量化研究辅助”。

主要交付物：

- 项目立项书。
- 精益画布。
- 因子假设说明。
- 回测指标解释。
- 答辩 PPT 和演示脚本。
- 评委问题回答清单。

优先任务：

- 第 1 天确定 MVP 行业和事件类型。
- 第 2 天定稿因子假设和回测指标。
- 第 3-5 天和成员 B、C 对齐数据字段、Demo 页面和答辩故事。

### 成员 B：数据工程 / LLM Agent / 事件谓词流水线

核心职责：

- 收集和整理文本数据：政策、新闻、公告、互动问答。
- 建立原始文本表、实体链接表、事件表、谓词表。
- 设计并实现 LLM 事件抽取 prompt。
- 设计并实现谓词判断 prompt。
- 输出结构化事件和事件-谓词矩阵。

主要交付物：

- `data/sample/raw_documents.csv`
- `data/sample/entity_links.csv`
- `data/sample/events.csv`
- `data/sample/predicates.csv`
- `src/pipeline/extract_events.py`
- `src/pipeline/ground_predicates.py`
- 事件抽取与谓词判断 prompt。

优先任务：

- 第 1 天整理股票池和文本样本来源。
- 第 2-3 天做 30-50 条样本文本的人工/半自动标注。
- 第 4-5 天跑通“文本 -> 事件 JSON -> 谓词 JSON”最小链路。

### 成员 C：工程实现 / 回测系统 / 可视化 Demo

核心职责：

- 搭建代码工程结构。
- 实现规则归纳、因子生成和基础回测。
- 实现 Demo 页面，展示文本、事件、谓词、规则、因子和回测结果。
- 负责项目可运行性、环境说明和演示稳定性。

主要交付物：

- `src/pipeline/induce_rules.py`
- `src/pipeline/generate_factors.py`
- `src/backtest/factor_backtest.py`
- `app/` 可视化 Demo。
- `README.md` 运行说明。
- `outputs/` 回测图表和自动报告。

优先任务：

- 第 1 天搭建项目目录和基础脚本入口。
- 第 2-3 天准备行情数据读取、收益计算、IC/Rank IC。
- 第 4-5 天跑通“谓词表 -> 规则 -> 因子 -> 回测结果”最小链路。

## 2. 三人协作边界

| 模块 | 主负责人 | 协作人 | 完成标准 |
|---|---|---|---|
| MVP 范围确定 | A | B、C | 明确行业、事件、股票池、周期、因子 |
| 数据样本 | B | A | 至少 100 条文本，字段完整 |
| 事件抽取 | B | A | 输出结构化事件表，抽样可解释 |
| 谓词 schema | A、B | C | 8-12 个谓词，能被程序读取 |
| 规则归纳 | C | A | 输出 Top-K 规则及评分 |
| 因子定义 | A | C | 公式、窗口、方向、标准化清楚 |
| 回测框架 | C | A | IC、Rank IC、分组收益、多空收益可运行 |
| Demo 页面 | C | A、B | 可完整演示一条链路 |
| 答辩材料 | A | B、C | PPT、脚本、FAQ、截图齐全 |

## 3. MVP 推荐选择

建议第一版不要做全市场，也不要覆盖所有舆情类型。

推荐方案：

- 行业：新能源或半导体。
- 事件：政策利好 + 市场关注度上升。
- 股票池：30-80 只行业股票。
- 时间周期：2024-01-01 至 2026-06-30。
- 文本来源：政策文件、新闻摘要、上市公司公告、互动问答。
- 因子：`policy_attention_momentum_score`
- 回测：周频调仓，持有 5 或 10 个交易日。
- 展示：事件抽取、谓词矩阵、规则触发、因子排名、回测图、自动报告。

第一版核心假设：

当政策利好直接作用于公司主营业务，且相关文本关注度在短期内加速上升时，相关股票可能出现短期主题动量或成交活跃度提升。

## 4. 第一周启动计划

### Day 1：定题和建仓库结构

目标：让项目从概念变成可执行工程。

A 负责：

- 确认最终 MVP 行业和事件类型。
- 写出 1 页因子假设：为什么这个事件可能有效。
- 列出答辩故事线：痛点、创新、Demo、回测、价值。

B 负责：

- 建立股票池清单。
- 收集 20-30 条示例文本。
- 初步设计 `raw_documents.csv` 字段。

C 负责：

- 建立目录结构。
- 写 `README.md` 初版。
- 准备 Python 环境和依赖清单。

当天完成标准：

- 有一个明确 MVP 题目。
- 有一批样本文本。
- 仓库能看到基本目录和运行说明。

### Day 2：数据 schema 和 prompt

目标：固定中间数据结构，让 Agent 之间能交接。

A 负责：

- 定义因子计算需要哪些字段。
- 定义回测评估指标和展示口径。

B 负责：

- 设计事件抽取 JSON schema。
- 设计谓词 schema。
- 编写事件抽取 prompt 和谓词判断 prompt。

C 负责：

- 编写 CSV/JSON 读取脚本。
- 准备行情数据格式。
- 写收益率计算基础函数。

当天完成标准：

- `raw_documents`、`events`、`predicates` 三张表字段确定。
- prompt 能对 3-5 条文本输出结构化结果。

### Day 3：跑通前半条链路

目标：完成“文本 -> 事件 -> 谓词”。

A 负责：

- 审核抽取结果是否符合金融逻辑。
- 标注 10 条高质量示例作为 Demo 案例。

B 负责：

- 跑 30-50 条文本样本。
- 修正 prompt，降低输出不稳定性。
- 保存事件表和谓词表。

C 负责：

- 写数据校验脚本。
- 保证事件表、谓词表能被后续规则模块读取。

当天完成标准：

- 至少 30 条文本完成事件抽取和谓词判断。
- 输出文件字段稳定，能被程序读取。

### Day 4：跑通后半条链路

目标：完成“谓词 -> 规则 -> 因子 -> 回测”。

A 负责：

- 定义规则筛选标准。
- 判断 Top-K 规则是否有金融含义。

B 负责：

- 补充样本和人工校正谓词。
- 给每个谓词保留证据片段和理由。

C 负责：

- 实现候选规则搜索。
- 实现基础因子计算。
- 实现 IC、Rank IC、分组收益。

当天完成标准：

- 至少产生 3-5 条候选规则。
- 能输出一版因子值和基础回测指标。

### Day 5：整合 Demo 和复盘

目标：形成可以演示的第一版闭环。

A 负责：

- 写第一版自动研究报告模板。
- 整理周复盘：哪些有效、哪些需要调整。

B 负责：

- 准备 Demo 输入样本。
- 整理事件和谓词解释案例。

C 负责：

- 做一个最简 Demo 页面或 notebook。
- 展示输入文本、事件表、谓词矩阵、规则、回测结果。

当天完成标准：

- 能从样本文本展示到回测结果。
- 有 1 个可解释案例。
- 有下一周优化清单。

## 5. 每日协作机制

每天固定 20 分钟站会：

- 昨天完成了什么。
- 今天要交付什么。
- 当前卡点是什么。
- 是否影响其他人的输入输出。

每天必须更新：

- 数据文件是否有新版本。
- 代码是否能运行。
- Demo 是否还能完整走通。
- 文档是否记录了关键决策。

每两天做一次小验收：

- Day 2 验收 schema 和 prompt。
- Day 4 验收规则和回测。
- Day 5 验收第一版闭环。

## 8. 本周最小成功标准

本周不追求功能完整，追求闭环跑通。

最低标准：

- 选定 1 个行业。
- 选定 1 类事件。
- 收集 100 条以内小样本。
- 跑通 30 条文本的事件抽取和谓词化。
- 归纳出 3 条以上候选规则。
- 生成 1 个因子。
- 跑出基础回测结果。
- 有一个可以讲清楚的案例。

理想标准：

- Demo 页面能展示完整链路。
- 自动生成一页研究报告。
- 回测图表包括 IC、分组收益、多空收益。
- PPT 已有 50% 内容。

## 9. 注意事项

- 不要把项目讲成“AI 炒股”。
- 不要让 LLM 直接预测涨跌。
- 不要只做情绪分析。
- 不要追求一开始就覆盖全市场。
- 不要为了好看而忽略未来函数。
- 每个因子结论都要有回测或审计提示。
- 所有 Demo 输出都要能追溯到文本、事件、谓词和规则。

## 10. 下一步建议

完成本文档后，下一步应立即补齐三类东西：

- 工程骨架：目录、README、依赖说明。
- 样本数据：股票池、文本样本、行情样本。
- 最小脚本：事件抽取、谓词判断、规则归纳、回测。

只要第一周能跑通一条完整链路，后续几周就是扩数据、稳回测、做可视化和打磨答辩。
