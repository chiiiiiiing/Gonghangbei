## 一、本轮把什么问题解决了

原演示端存在三类口径风险：前端和 B 线各维护一套实体、事件、谓词与规则；新输入文本会临时生成一组貌似属于它的回测指标；README 仍把 Flask 项目描述成纯静态页面。这样虽然界面能动，但评委继续追问时，很难证明页面数字与正式 CSV 是同一条链路。

本轮完成以下收口：

1. `src/pipeline/ground_predicates_rule_based.py` 新增单事件函数，批处理和在线分析共同调用。
2. `src/pipeline/live_analysis.py` 复用正式实体别名、事件判断、谓词 Schema 和冻结规则。
3. 新文本只生成“候选因子”，不读取未来收益，也不写回历史样本。
4. 历史回测只读取正式流水线生成的指标、分组收益和 Rank IC 时序。
5. 页面明确展示来源类型、来源名称、首次公开日期和正文链接，来源信息会参与谓词判断。
6. 删除原演示端中没有正式 CSV 支撑的 Sharpe、年化收益、最大回撤和临时多空曲线。
7. Plotly 改成本地文件，断网仍能展示图表。

## 二、成品现在怎样运行

```text
新文本与来源元数据
-> 正式实体链接逻辑
-> 正式事件类型判断
-> 19 个锁定谓词
-> 12 条冻结合格规则匹配
-> 规则评分 × 证据强度/事件先验
-> 新文本候选因子与可追溯研究记录

固定历史文本与行情
-> 未来收益对齐
-> 规则搜索与因子样本
-> 分组收益、Rank IC、未来函数审计
-> Demo 历史回测参考
```

两条链路在规则和字段上相连，在时间上隔离。新事件要等未来收益真实发生后，才可在下一轮研究中加入历史样本。

## 四、你现在先做什么

第一优先级是完成 `查看材料/谓词人工抽检样本.csv`。在结果列只填写 `pass`、`revise`、`drop`：

- `pass`：谓词值和理由都合理。
- `revise`：事件保留，但谓词值或理由需要修改；备注中写期望值和原因。
- `drop`：事件本身不该进入该谓词判断；备注中写明证据不足在哪里。

完成后运行：

```bash
.venv/bin/python scripts/validate_manual_review_results.py
```

不要直接手改生成后的 `predicates.csv`。把 revise/drop 结论交给 B 规则代码处理，再用 `run_pipeline.py --preserve-inputs` 安全复跑。
