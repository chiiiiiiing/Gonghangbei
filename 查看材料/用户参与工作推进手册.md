# AlphaLens 用户参与工作推进手册

生成日期：2026-07-15

本报告仅供研究参考，不构成投资建议

## 当前你要推进的事

当前自动线已经把文本、行情、事件、谓词、规则、因子、回测审计和报告串通。你接下来不需要从头重建项目，重点是给“自动候选版”补上人工确认记录，让它可以被 A、C 和最终 PPT 安全使用。

你的工作分成 6 组：

1. 人工抽查联网替换后的真实文本来源。
2. 人工复核真实前复权行情口径。
3. 人工抽检事件抽取结果。
4. 人工抽检谓词判断结果。
5. 与 A 确认金融 Schema 和对外表述。
6. 与 C 联调真实数据，并做 PPT/CSV 数字交叉检查。

不要做的事：

- 不要运行 `--force-sample-generation`。
- 不要改 `参考文档/数据格式规范.md` 锁定的 CSV 字段名。
- 不要把系统描述成预测股价或给投资建议。
- 不要删除任何报告中的免责声明。
- 不要把 `data/raw/`、`data/processed/`、`data/external/` 放入 Git。

## 推荐推进顺序

### 第 1 步：先做文本来源人工抽查

目标：证明 `data/sample/raw_documents.csv` 里的联网替换文本不是随便拼出来的，每条关键样本都能追溯到正文、公告 PDF 或问答详情页。

使用文件：

- `查看材料/源文本核验队列.csv`
- `data/sample/raw_documents.csv`
- `查看材料/真实文本来源获取记录.md`
- `查看材料/真实文本核验进度.md`

当前状态：

- 文本总数：120 条。
- policy / announcement / news / ir_qa 各 30 条。
- P0 候选摘要替换进度：100/100。
- 当前队列已降为 P1 人工抽查，不是 P0 缺口。

建议抽查数量：

| 来源类型 | 最低抽查数 | 优先看什么 |
|----------|------------|------------|
| policy | 20 | 中国政府网、工信部、发改委、国家能源局页面 |
| announcement | 20 | 巨潮资讯网 PDF，标题和日期是否匹配 |
| news | 20 | 财经媒体或行业网站正文页，避免首页和列表页 |
| ir_qa | 10 | 深交所互动易详情页，问题、回复、公司和日期是否一致 |

操作步骤：

1. 打开 `查看材料/源文本核验队列.csv`。
2. 按 `source_type` 筛选一种来源类型，从 policy 开始。
3. 优先抽查 `doc_id` 靠前和标题看起来泛化的样本。
4. 打开该行 `url`。
5. 核对页面是否为正文、公告 PDF 或问答详情页，不接受网站首页、频道页、搜索页。
6. 核对 `title` 是否与页面主题一致。
7. 核对 `publish_time` 是否是首次公开日期，格式必须是 `YYYY-MM-DD`。
8. 打开 `data/sample/raw_documents.csv`，按 `doc_id` 找到同一行。
9. 核对 `content` 是否包含两类信息：
   - 原文摘要：只写摘要，不复制大段正文。
   - 项目关联：说明它为什么与新能源股票池或主营链条相关。
10. 如果发现错误，直接修 `raw_documents.csv` 中该行的 `title`、`content`、`publish_time`、`source_name`、`url`。
11. 不要修改 `doc_id` 和 `source_type`。
12. 每完成一批，告诉 Codex “我完成了文本抽查第 X 批，请安全复跑验证”。

通过标准：

- URL 可以追溯到具体正文、PDF 或问答详情页。
- 日期为首次公开日期，不是抓取日期。
- content 不包含收益判断、股价方向判断或买卖建议。
- 公司关联和产业链关联没有编造。
- CSV 字段名和字段顺序不变。

建议记录方式：

在 `查看材料/源文本核验队列.csv` 外另开一列记录也可以，但更推荐把发现的问题直接整理给 Codex，例如：

```text
文本抽查第 1 批：
S001 pass
S006 pass
S011 revise：日期应为 2025-01-14，不是 2024-01-20
S016 drop：问答详情页公司不匹配，请替换
```

### 第 2 步：复核真实前复权行情口径

目标：确认 `data/sample/market_data.csv` 可以作为正式候选行情输入，或者决定替换为 Wind、Choice、Tushare、AkShare 等更明确的前复权数据。

使用文件：

- `data/sample/market_data.csv`
- `查看材料/真实行情获取记录.md`
- `查看材料/真实行情校验报告.md`
- `查看材料/真实行情导入模板.csv`

当前状态：

- 行情来源：东方财富历史 K 线接口。
- 参数：日频 `klt=101`，前复权 `fqt=1`。
- 覆盖：30 只股票，18,002 行。
- 日期范围：2024-01-02 至 2026-06-30。
- 校验 errors：0。
- 仍有 warnings：
  - 个别股票日期覆盖少于最大覆盖。
  - `adj_factor` 唯一值为 1，因为接口返回前复权价格但不直接返回复权因子。

你需要做的判断：

| 判断项 | 可接受结论 | 后续动作 |
|--------|------------|----------|
| 东方财富 `fqt=1` 是否可作为比赛候选前复权口径 | 接受 | 在 PPT 或答辩中说明来源和限制 |
| 是否必须有真实 `adj_factor` 序列 | 必须 | 换数据源后重写 `market_data.csv` |
| 覆盖不均是否可接受 | 可接受 | 在报告中保留 warning |
| 覆盖不均是否影响回测样本 | 影响 | 补齐缺失交易日或缩短窗口 |

如果你决定保留当前行情：

1. 在 `查看材料/真实行情获取记录.md` 中保留来源说明。
2. 在答辩中说“使用东方财富前复权价格候选版，复权因子字段为占位，正式金融数据源可替换”。
3. 不把它说成经过数据供应商最终确认的正式行情。

如果你决定替换行情：

1. 按 `查看材料/真实行情导入模板.csv` 准备新文件。
2. 字段必须严格为 `trade_date,stock_code,open,high,low,close,volume,adj_factor`。
3. 股票代码必须是 6 位字符串，不带交易所后缀。
4. 日期必须是 `YYYY-MM-DD`。
5. 空值用空字符串，不写 `NULL`、`NA`、`NaN`。
6. 覆盖 2024-01-01 至 2026-06-30 的交易窗口。
7. 写入 `data/sample/market_data.csv`。
8. 让 Codex 运行：

```bash
.venv/bin/python scripts/validate_real_market_data.py --input data/sample/market_data.csv
.venv/bin/python run_pipeline.py --preserve-inputs
```

### 第 3 步：人工抽检事件结果

目标：确认事件类型、事件时间、股票关联和证据片段是否可解释。

使用文件：

- `查看材料/事件人工抽检样本.csv`
- `data/sample/events.csv`
- `data/sample/raw_documents.csv`
- `查看材料/人工抽检结果校验报告.md`

当前状态：

- 事件总数：60。
- 抽检样本：10 条。
- `manual_review_result` 目前为空。

操作步骤：

1. 打开 `查看材料/事件人工抽检样本.csv`。
2. 逐行查看 `doc_id`、`title`、`stock_code`、`event_type`、`event_time`、`evidence_text`。
3. 回到 `raw_documents.csv`，按 `doc_id` 查看原文摘要。
4. 判断事件类型是否合理。
5. 判断股票关联是否合理。
6. 判断事件时间是否不早于文本发布日期，且不晚于可公开信息日期。
7. 判断 `evidence_text` 是否能支撑事件。
8. 在 `manual_review_result` 填：
   - `pass`：无需修改。
   - `revise`：事件可保留，但字段需要修改。
   - `drop`：事件不应进入正式数据。
9. 在 `manual_comment` 写具体原因。

事件抽检判断规则：

| 字段 | 通过标准 |
|------|----------|
| event_type | 与文本事实匹配，不为了凑规则强行分类 |
| stock_code | 文本明确涉及该公司，或明确涉及其主营产业链 |
| event_time | 信息公开日，必须为 `YYYY-MM-DD` |
| evidence_strength | 0 到 1，权威公告/官方政策通常更高 |
| evidence_text | 能让 A/C 快速理解为什么抽取这个事件 |

如果填了 `revise`：

1. 在 `manual_comment` 写清楚建议修改字段。
2. 不要直接大批量改 `events.csv`，先把一批问题告诉 Codex。
3. Codex 会按字段契约修正、重跑谓词和验证。

如果填了 `drop`：

1. 写清楚为什么不应保留。
2. 暂时不要删除整行。
3. 让 Codex 统一处理下游引用，避免 `predicates.csv` 和规则输出断链。

完成后运行或让 Codex 运行：

```bash
.venv/bin/python scripts/validate_manual_review_results.py
```

### 第 4 步：人工抽检谓词结果

目标：确认每个事件被转成谓词时，true/false/分数是否符合金融语义。

使用文件：

- `查看材料/谓词人工抽检样本.csv`
- `data/sample/predicates.csv`
- `参考文档/事件与谓词Schema.md`
- `查看材料/A口径确认建议稿.md`

当前状态：

- 谓词总数：660。
- 抽检样本：60 条。
- `manual_review_result` 目前为空。

操作步骤：

1. 打开 `查看材料/谓词人工抽检样本.csv`。
2. 按 `event_id` 分组看同一事件下多个谓词。
3. 查看 `predicate_name`、`value`、`confidence`、`rationale`。
4. 对照 `参考文档/事件与谓词Schema.md` 判断口径。
5. 在 `manual_review_result` 填 `pass`、`revise` 或 `drop`。
6. 在 `manual_comment` 写具体理由。

谓词重点检查：

| 谓词 | 重点判断 |
|------|----------|
| has_policy_support | 只有政策支持或补贴、减税、消纳、行动方案等才应为 true |
| policy_directly_related_to_business | 是否直接影响公司主营或核心产业链 |
| event_mentions_core_product | 是否明确涉及产品、技术、产能、订单或核心业务 |
| evidence_from_authoritative_source | 政府、交易所、巨潮、互动易等通常为 true，普通媒体需谨慎 |
| social_attention_spikes | 是否有关注度扩散证据，不能只因有一篇新闻就为 true |
| investor_questions_increase | 互动问答压力或集中提问才为 true |
| management_response_vague | 回复是否实质含糊、回避或缺少量化信息 |
| announcement_contains_uncertainty | 公告是否有不确定、风险、尚需审批、可能变化等表述 |
| event_evidence_strength | 0 到 1 分数，必须与来源权威性和证据直接性一致 |
| event_has_short_term_price_impact | 中性理解为历史关注强度，不要写成预测股价 |

合法值：

- 布尔谓词只能填 `true` 或 `false`。
- 分数谓词必须是 0 到 1 的数字字符串。
- 人工结论只能填 `pass`、`revise`、`drop` 或暂时留空。

完成后让 Codex 运行：

```bash
.venv/bin/python scripts/validate_manual_review_results.py
.venv/bin/python run_pipeline.py --preserve-inputs
```

### 第 5 步：找 A 确认金融 Schema

目标：让项目负责人确认事件类型、谓词和对外表述边界，避免 B/C 自动线在金融逻辑上跑偏。

使用文件：

- `查看材料/A口径确认建议稿.md`
- `参考文档/事件与谓词Schema.md`
- `查看材料/答辩问答素材.md`

你需要让 A 明确回答：

1. `policy_support` 是否包括产业行动方案、税收优惠、补贴、目录管理、消纳政策。
2. `capacity_expansion` 是否包括募投项目、产能建设、海外认证、交付能力、评级报告中的产能描述。
3. `investor_question_pressure` 是关注度信号、风险信号，还是二者都可。
4. `social_attention_spikes` 的证据门槛是什么。
5. `event_has_short_term_price_impact` 是否需要改成更中性的名称。
6. 答辩中是否接受“另类因子研究信号”这个说法。
7. 是否明确禁止任何“预测股价、推荐买卖、保证收益”的措辞。

建议记录格式：

```text
A 口径确认记录：
日期：2026-xx-xx
参与人：
1. policy_support：采用/调整为……
2. capacity_expansion：采用/调整为……
3. investor_question_pressure：采用/调整为……
4. 对外表述：允许……，禁止……
需 B 修改：
需 C 修改：
```

确认后，把记录交给 Codex。Codex 可以继续做：

- 更新 `参考文档/事件与谓词Schema.md` 或新增确认记录。
- 修正事件和谓词规则。
- 重跑流水线和报告。

## 90 分钟工作安排

如果你今天只想推进一轮，按这个节奏走：

| 时间 | 动作 | 产物 |
|------|------|------|
| 0-10 分钟 | 打开本手册、`人工待办.md`、`源文本核验队列.csv` | 明确今天批次 |
| 10-45 分钟 | 抽查政策和公告各 5-10 条 | pass/revise/drop 记录 |
| 45-65 分钟 | 抽查事件样本 5 条 | 更新事件人工抽检表 |

如果你有半天时间，建议顺序是：

1. 完成政策 20 条抽查。
2. 完成公告 20 条抽查。
3. 完成事件人工抽检 10 条。
4. 完成谓词人工抽检 60 条中的 30 条。
5. 让 Codex 复跑并更新报告。

## 最终交付前冻结标准

满足以下条件后，可以进入 PPT 数字冻结：

- 文本来源人工抽查已覆盖第一批目标：政策 20、公告 20、新闻 20、互动问答 10。
- 事件人工抽检 10 条均为 `pass`，或 `revise/drop` 已处理完。
- 谓词人工抽检 60 条均为 `pass`，或 `revise/drop` 已处理完。
- 行情口径已有人工确认记录。
- A 已确认金融 Schema 和对外表述边界。
- C 已确认 CSV 读取、收益对齐和回测口径。
- `validate_b_data.py` 输出 `errors=0`。
- `validate_research_outputs.py` 输出 `research_output_errors=0`。
- `validate_delivery_package.py` 输出 `delivery_errors=0`。
- PPT 中所有数字能在 CSV 或查看材料中找到来源。

## 边界提醒

- AlphaLens 是量化研究助手，不预测股票价格，不提供投资建议。
- 因子和回测用于研究假设验证，不代表收益承诺。
- 人工确认的价值是保证数据事实、金融语义和展示数字一致。
- 自动脚本可以帮你重跑、校验、更新材料，但 A/C 签字确认和事实抽查仍需要人完成。
