# AlphaLens 从输入文本到因子回测全流程

> 本报告仅供研究参考，不构成投资建议

## 1. 一句话总览

AlphaLens 的完整链路是：

```text
金融文本
→ 股票实体链接
→ 股票-事件抽取
→ 事件谓词判断
→ 谓词矩阵
→ 自动规则生成
→ 规则触发生成因子取值
→ 事件级回测验证
→ 因子研究报告和 Demo 展示
```

它不是：

```text
文本 → AI 预测股价
```

而是：

```text
文本 → 可解释结构化信号 → 可回测研究因子
```

核心边界是：系统不提供投资建议，不声称预测股票价格；回测只用于研究验证。

## 2. 输入文本层：raw_documents.csv

输入是一批金融文本，每行是一篇文本：

```text
doc_id
source_type
title
content
publish_time
source_name
url
```

文本来源可以是：

```text
policy：政策文件
announcement：上市公司公告
news：财经新闻
ir_qa：投资者互动问答
```

这一层只回答一个问题：

```text
我们有哪些原始金融文本？
```

它还不是事件、不是规则、不是因子。

## 3. 股票关联层：entity_links.csv

一篇文本可能关联 0 只、1 只或多只股票。

例如：

```text
新能源汽车以旧换新政策延续，利好整车和动力电池产业链。
```

它可能关联：

```text
002594 比亚迪
300750 宁德时代
600104 上汽集团
601633 长城汽车
```

这一步生成 `entity_links.csv`，回答：

```text
这篇文本和哪些股票存在研究关联？
```

注意：这里不是判断“利好就会上涨”，只是建立文本和股票池之间的关联。

## 4. 事件层：events.csv

在股票关联之后，系统把文本转换成“股票-事件”。

如果一篇文本关联 4 只股票，就可能生成 4 个事件：

```text
E001 - 002594 - policy_support
E002 - 300750 - policy_support
E003 - 600104 - policy_support
E004 - 601633 - policy_support
```

`events.csv` 的关键字段是：

```text
event_id：事件 ID
doc_id：来源文本
stock_code：关联股票
event_type：事件类型
event_time：事件日期
impact_path：影响路径描述
evidence_text：证据片段
evidence_strength：证据强度
```

这一层回答：

```text
某篇文本对某只股票形成了什么类型的结构化事件？
```

事件是后续因子生成的基础单位。项目里真正往下走的不是“整篇文本”，而是“股票-事件”。

## 5. 谓词层：predicates.csv

谓词是事件的结构化特征，可以理解成一个个可解释判断。

例如某个事件可能被判断为：

```text
has_policy_support = true
event_mentions_core_product = true
source_government_or_exchange = true
policy_attention_followup = true
event_evidence_strength = 0.94
event_has_short_term_price_impact = 0.78
```

`predicates.csv` 是长表：

```text
event_id
predicate_name
value
confidence
rationale
```

也就是说，同一个 `event_id` 会对应多行谓词判断。

当前谓词库分成两类：

```text
boolean 谓词：true / false
score 谓词：0 到 1 的分数
```

boolean 谓词用于组合规则；score 谓词主要用于因子权重。

## 6. 当前谓词库怎么理解

当前谓词库包括：

```text
has_policy_support
policy_directly_related_to_business
event_mentions_core_product
evidence_from_authoritative_source
source_government_or_exchange
source_company_announcement
source_major_media
social_attention_spikes
policy_attention_followup
institutional_attention_increases
investor_questions_increase
management_response_vague
announcement_contains_uncertainty
risk_or_uncertainty_disclosure
demand_side_policy
supply_side_policy
capacity_policy_support
event_evidence_strength
event_has_short_term_price_impact
```

它们各自承担不同角色：

| 类型 | 代表谓词 | 用途 |
|------|----------|------|
| 政策类 | `has_policy_support`, `demand_side_policy`, `supply_side_policy` | 描述政策支持路径 |
| 来源类 | `source_government_or_exchange`, `source_company_announcement`, `source_major_media` | 区分证据来源 |
| 产品类 | `event_mentions_core_product` | 判断是否触及公司核心业务 |
| 关注类 | `social_attention_spikes`, `policy_attention_followup`, `institutional_attention_increases` | 描述关注扩散或机构关注 |
| 风险类 | `risk_or_uncertainty_disclosure`, `announcement_contains_uncertainty` | 描述风险披露或不确定性 |
| 权重类 | `event_evidence_strength`, `event_has_short_term_price_impact` | 调整因子强度 |

## 7. 谓词矩阵：predicate_matrix.csv

规则生成需要一行一个事件，所以系统把 `predicates.csv` 转成宽表 `predicate_matrix.csv`。

长表是：

```text
E001, has_policy_support, true
E001, event_mentions_core_product, true
E001, policy_attention_followup, false
```

宽表是：

```text
event_id | stock_code | event_type | has_policy_support | event_mentions_core_product | policy_attention_followup | ...
E001     | 002594     | policy_support | true | true | false | ...
```

这一层回答：

```text
每个事件在所有谓词维度上的取值是什么？
```

## 8. 历史收益标签：event_forward_returns.csv

为了研究规则有没有价值，系统会给历史事件挂上未来收益标签。

当前逻辑是：

```text
entry_trade_date：事件日之后的第一个交易日
forward_return_5d：从入场价到第 5 个交易日收盘的收益
forward_return_10d：从入场价到第 10 个交易日收盘的收益
```

这一步只用于历史验证，不用于新文本当下生成因子。

关键边界：

```text
event_time < entry_trade_date
```

即事件必须先发生，收益窗口必须在事件之后，避免未来函数。

## 9. 为什么历史事件不需要完全相同

现实里几乎不会有完全相同的金融事件。

AlphaLens 回测的不是“同一条新闻”，而是“同一种可解释事件模式”。

例如三条不同文本：

```text
商务部推动新能源汽车以旧换新，整车产业链关注升温。
国务院发布设备更新方案，动力电池装车量受到市场关注。
多家媒体报道新能源汽车渗透率提升，核心零部件公司受关注。
```

它们不完全相同，但可能共享谓词结构：

```text
event_mentions_core_product = true
policy_attention_followup = true
social_attention_spikes = true
```

只要它们触发相同规则，就会形成同一类研究信号。

所以项目做的是：

```text
具体文本
→ 抽象成谓词
→ 归纳成规则
→ 形成可复用因子
```

## 10. 自动规则生成：rules.csv

规则是谓词的组合条件。

例如：

```text
R004 =
event_mentions_core_product
AND policy_attention_followup
```

它的含义是：

```text
事件提到了核心产品，并且有政策后续关注扩散线索。
```

当前规则不是固定手写 4 条，而是自动从 boolean 谓词中枚举 2 阶和 3 阶组合。

自动规则生成流程：

```text
1. 从 predicate_matrix.csv 读取所有 boolean 谓词
2. 排除完全不触发的谓词组合
3. 枚举 2 个或 3 个谓词的 AND 组合
4. 在 2024-2025 discovery 区间统计触发事件
5. 计算支持度、胜率、平均收益、证据强度、股票覆盖
6. 达到阈值则标记为 qualified
7. 未达到但有观察价值则保留为 candidate
```

当前合格标准是：

```text
support_count >= 5
win_rate >= 50%
avg_forward_return_5d >= 0
avg_evidence_strength >= 0.75
stock_count >= 5
max_terms <= 3
```

`rules.csv` 的核心字段是：

```text
rule_id
rule_name
condition
target_label
support_count
positive_count
win_rate
avg_forward_return_5d
score
status
```

只有：

```text
status = qualified
```

的规则会进入因子生成。

## 11. 规则分数怎么来

规则分数来自历史 discovery 样本中的统计表现。

规则评分当前考虑：

```text
win_rate：触发后 5 日收益为正的比例
avg_forward_return_5d：触发后平均 5 日收益
support_count：触发次数
stock_count：覆盖股票数
avg_evidence_strength：平均证据强度
```

可以理解为：

```text
规则分数 = 历史上同类事件模式的研究表现
```

它不是新文本的未来收益，也不是价格预测。

新文本触发规则时，只继承这条规则在历史 discovery 区间里估计出的分数。

## 12. 规则和因子的关系

三者关系是：

```text
谓词：事件的原子特征
规则：谓词组合出的解释条件
因子：规则触发后生成的数值信号
```

规则不是因子。

更准确地说：

```text
规则决定是否触发信号；
规则分数决定信号基础强度；
事件证据强度决定当前事件权重；
最终数值才是 factor_value。
```

例如：

```text
谓词：
event_mentions_core_product = true
policy_attention_followup = true

规则：
R004 = event_mentions_core_product AND policy_attention_followup

因子取值：
某只股票在某个交易日产生 policy_signal_score = 1.23
```

## 13. 因子定义和因子取值

这是最容易混的地方。

因子定义是：

```text
policy_signal_score
attention_signal_score
composite__attention_signal__policy_signal_score
```

因子取值是：

```text
某只股票
某个日期
某个 factor_name
对应的 factor_value
```

`factors.csv` 的一行是一个因子取值样本，不是一个新的因子定义。

粒度是：

```text
trade_date + stock_code + factor_name
```

例如：

```text
2024-02-21
300750
composite__attention_signal__policy_signal_score
factor_value = 1.089574
```

这表示：

```text
300750 在 2024-02-21 形成了一个复合事件因子取值。
```

## 14. 一篇文本为什么可能产生 0 行、1 行或多行因子取值

一篇文本不会天然等于一个因子。

它要先经过：

```text
文本 → 股票关联 → 事件 → 谓词 → 规则触发 → 因子取值
```

### 0 行因子取值

如果文本没有关联股票、没有抽出有效事件，或事件没有触发任何合格规则，就不会进入 `factors.csv`。

### 1 行因子取值

如果文本关联 1 只股票，抽出 1 个事件，并触发合格规则，就生成 1 行因子取值。

### 多行因子取值

如果文本关联多只股票，就可能生成多个股票-事件，每个股票-事件各自产生一行因子取值。

例如同一篇政策文本关联 4 只股票：

```text
002594 比亚迪
300750 宁德时代
600104 上汽集团
601633 长城汽车
```

它可能生成：

```text
002594 policy_signal_score 1.80
300750 policy_signal_score 1.35
600104 policy_signal_score 0.95
601633 policy_signal_score 1.20
```

这不是 4 个不同因子，而是同一个 `policy_signal_score` 因子定义在 4 只股票上的 4 个取值。

## 15. 复合因子怎么理解

如果一个事件同时触发多个规则族，系统会生成复合因子名。

例如：

```text
R004 属于 policy_signal
R005 属于 attention_signal
```

同一个事件同时触发 R004 和 R005 时，因子名就是：

```text
composite__attention_signal__policy_signal_score
```

这表示：

```text
这个事件同时具有政策信号和关注扩散信号。
```

当前实现是一事件生成一行因子取值，但这一行可以记录多个触发规则：

```text
trigger_rule_ids = R004|R005
```

这样做可以避免同一个事件在回测中被重复计样本，同时保留规则溯源。

## 16. 多规则怎么量化成 factor_value

当前事件级因子公式是：

```text
raw_score = sum(触发的合格规则 score)

factor_value =
  raw_score
  * (0.7 * event_evidence_strength
     + 0.3 * event_has_short_term_price_impact)
```

含义是：

```text
规则历史表现
× 当前事件证据强度/事件先验
= 当前事件因子值
```

如果事件只触发一条规则：

```text
raw_score = R004.score
```

如果事件触发多条规则：

```text
raw_score = R004.score + R005.score + R009.score
```

再乘以事件权重。

## 17. factors.csv 怎么用于回测

`factors.csv` 是事件级历史因子样本。

每行包含：

```text
trade_date
stock_code
factor_name
factor_value
raw_score
trigger_event_ids
trigger_rule_ids
forward_return_5d
future_info_ok
```

回测逻辑是：

```text
1. 取所有有 forward_return_5d 的因子样本
2. 按 factor_value 从低到高排序
3. 分成 G1-G5 五组
4. 计算每组未来 5 日平均收益
5. 用 G5 - G1 作为高低组收益差
6. 按日期计算 Rank IC
7. 统计事件样本数、正收益比例、未来函数审计结果
```

这里回测的是：

```text
因子值的排序能力
```

不是完整交易策略，也不是每日调仓组合。

更接近：

```text
事件研究 / event study
```

## 18. factor_snapshot.csv 是什么

`factors.csv` 是历史事件级样本；`factor_snapshot.csv` 是最后交易日的股票截面快照。

它做的是：

```text
1. 对每只股票累计截至最后交易日之前触发的规则事件
2. 对越久远的事件做时间衰减
3. 累加得到 stock_raw_score
4. 在行业内做 z-score
5. 输出当前截面排名
```

时间衰减公式：

```text
recency_decay = 0.5 ** (days_since / 45)
```

事件权重：

```text
event_weight = event_evidence_strength * recency_decay
```

股票原始分：

```text
stock_raw_score += sum(triggered_rule_scores) * event_weight
```

最后：

```text
factor_value = 行业内 z-score
```

这样可以减少不同行业文本密度差异带来的偏差。

## 19. 历史研究期和新文本应用期

项目要分成两个阶段理解。

### 历史研究期

可以使用历史事件后的 forward return 来评价规则：

```text
历史文本
→ 事件
→ 谓词
→ 自动规则
→ 规则评分
→ 因子样本
→ 回测验证
```

这一阶段是为了建立规则库和因子生成逻辑。

### 新文本应用期

新文本进来时，不能使用未来收益。

只能做：

```text
新文本
→ 股票关联
→ 事件抽取
→ 谓词判断
→ 匹配已有合格规则
→ 生成当下因子取值
```

未来 5 日收益只能等发生之后，再进入下一轮研究评价。

## 20. 当前最新输出应该怎么读

当前最新链路输出大致是：

```text
谓词：19 个
自动规则：18 条
合格规则：9 条
事件级因子样本：97 条
因子名：
  policy_signal_score
  attention_signal_score
  composite__attention_signal__policy_signal_score
```

当前回测摘要：

```text
event_factor_sample_count = 97
positive_forward_return_rate_5d = 57.73%
top_bottom_group_spread_5d = -2.16%
future_info_audit = pass
```

解读：

```text
触发规则的事件样本数量变多，且正收益比例尚可；
但高分组相对低分组的排序效果还不稳定；
说明当前规则库已经更可解释，但规则权重和去冗余仍需继续优化。
```

## 21. 当前最重要的限制

- 当前规则筛选仍是 Demo 级研究逻辑，不应包装成投资策略。
- `score` 型谓词中，`event_has_short_term_price_impact` 是事件类型先验，后续要继续校准。
- 多规则触发现在是简单加总，后续应加入规则去冗余，避免高度重叠规则重复加分。
- `factor_snapshot.csv` 是截面展示，不代表交易建议。
- 回测目前是事件级验证，不是完整组合回测。

## 22. 对外讲法

可以这样讲：

```text
AlphaLens 先把金融文本转成股票-事件级样本，再对每个事件判断可解释谓词。
系统在历史 discovery 样本中自动搜索谓词组合，形成规则库。
当事件触发合格规则时，系统结合规则历史分数、事件证据强度和事件先验生成因子取值。
最后通过事件后的收益窗口做回测审计，验证这些文本事件因子的研究价值。
```

边界必须保留：

```text
这不是 AI 炒股，不预测股票价格，不构成投资建议。
```

> 本报告仅供研究参考，不构成投资建议
